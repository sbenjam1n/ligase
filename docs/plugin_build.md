# ligase as a plugin — build, run, and how it is put together

ligase~ runs in a DAW as **VST3, VST2, CLAP, LV2, AU (macOS) and a JACK standalone**, with
stereo audio in (recording into the reel / sound-on-sound), stereo out, MIDI in, host
automation of every panel control, DAW transport → tempo clock, and full project state.
The plugin is built on [DPF](https://github.com/DISTRHO/DPF) (ISC licence, its own VST3
ABI implementation — no Steinberg SDK, no GPLv3 code), so the combined work stays under
ligase's GPL-2.0-only licence: **the plugin is distributable as-is**, which the plugdata
route (`Plans/vst_plugin.md` v1) never was.

## Build

```bash
git submodule update --init --recursive      # DPF (+ its pugl submodule)
make -C plugin/tests                         # engine identity gate (no DAW, no Pd needed)
make -C plugin -j8                           # every format for this OS -> plugin/bin/
make -C plugin/tests clap                    # end-to-end smoke test of the built CLAP
```

| OS | needs | produces (`plugin/bin/`) |
|---|---|---|
| Linux | gcc/g++, python3, X11/GL dev headers (`libx11-dev libxext-dev libxrandr-dev libxcursor-dev libdbus-1-dev libgl-dev`); **webkit2gtk at runtime** for the GUI | `ligase.vst3/`, `ligase.vst/`, `ligase.clap/`, `ligase.lv2/`, `ligase` (JACK) |
| macOS | Xcode command-line tools, python3 | the same + `ligase.component` (AU); GUI uses WKWebView |
| Windows | MinGW (DPF-supported; untested here) | GUI uses WebView2 |

Install by copying the bundle into the usual folder (`~/.vst3`, `~/Library/Audio/Plug-Ins/VST3`,
`~/.clap`, `~/.lv2`, `~/Library/Audio/Plug-Ins/Components`…). The GUI page lives inside each
bundle (`resources/index.html` — generated by `make -C plugin ui`).

## What is inside

```
plugin/
  pdshim.{c,h}         a minimal Pure Data API (class/method table, inlets/outlets, dsp_add, post,
                       gensym, canvas path helpers, logical clock) — ligase~.c compiles UNMODIFIED
  ligase_engine.{c,h}  the host facade: one engine = one ligase~ object; messages (typed or text),
                       CV inlets with the panel's 20 ms glide, 64-frame inner blocks, status readback
  engine/*.c           one-line wrappers that compile ../src/*.c inside the plugin tree
  ligase_params.h      GENERATED (docs/ui/emit_plugin.py): the host-parameter table from panel_layout.py
  LigasePlugin.*       the DPF DSP side: parameters, MIDI, transport clock, command queue, state
  LigaseUI.cpp         the DPF web-view UI: the SVG surface + shared panel brain (see docs/ui/panel_bridge.md)
  ui/                  bridge.js (page <-> plugin), page_template.html, build_page.py, params.json
  tests/               identity_test.c (the gate), clap_host_test.c (headless DAW-style host)
```

**The engine is the Pd engine.** `src/` is compiled as-is; `plugin/tests/identity_test.c`
re-runs `AUTOMATED_TEST_PROCEDURE.md` through the facade with Pd's own `noise~` sequence and
scheduler timing: the saved reel is **byte-identical** to the one Pd produces (RMS 0.372309,
132288 frames, playback buffer check 0.330109). Every engine change must keep that gate green
(`make -C plugin/tests`).

### Signal + control model
* Audio L/R → engine inlets 1/2 (record / monitor path); engine outlets 1/2 → output, MASTER gain applied.
* The 22 CV inlets and every message-bound panel control are **host parameters** in engine units
  (`docs/ui/emit_plugin.py` lists them; cutoff is logarithmic; grids are enumerated). Parameters
  are applied on the audio thread between inner blocks, like Pd messages between DSP ticks.
* **Knobs are the message base** (`panel_layout.INLET_SELECTORS`): the engine runs `headless 1`
  with its signal inlets unpatched and a CV knob's parameter is delivered as the inlet's message
  twin (`grainsize 0.25`), ramped over the panel's 20 ms glide as one message per inner block with
  the engine console quiet. That is what lets snapshot recall, the metasurface blend and XPNDR
  ASSIGN move every knob (a driving inlet would re-assert its value every block — the Pd panel's
  hardware model). The joystick is the message cursor (`morph <x> <y>`); only SMEAR MIX and MIDI
  NOTE (no message twin) drive their signal inlets. Stut mode remaps TIME/FDBK/TONE to
  `stut_reps`/`stut_reduction`/`stut_spacing` like the engine remaps the inlets.
* Everything else (matrix routings, XPNDR, SEQ/SCALE, morph surface, source shapes) is sent as
  engine **messages** from the GUI through the transient `cmd` state; heavy file operations
  (`load`/`save`/`morph_*` files) run on the caller thread while the audio thread mutes.
* Inner block = 64 frames (Pd's). Host buffers that are multiples of 64 run with **zero latency**;
  others report 64 frames of latency.

### MIDI
| message | effect |
|---|---|
| note on / off | `midi <note> <vel> <ch>` — chordal poly pool (up to 8 voices) when POLY is on, last-note mono otherwise; channel routing GRAIN ch / SMEAR ch parameters |
| velocity | scales LEVEL by `VELOCITY → LEVEL` amount |
| CC | default map: 1 dly mix · 7 level · 10 pan · 11 sos · 12 grainsize · 13 density · 14 speed · 15 start · 16 morph X · 17 morph Y · 64 play · 71 resonance · 74 cutoff · 91 dly feed · 93 smear mix · 94 filter mix (edit via the `midimap` state, one `cc=parameter_id` per line) |
| pitch bend | `pitch_fine` ± PITCH BEND RANGE cents |
| program change | `snapshot_recall <n>` |
| CC 120/123 | all notes off |

### Transport
With CLOCK SOURCE = HOST (default) the plugin sends the engine a clock bang at every DAW beat,
stamped with the exact beat time, so BPM detection is exact and every quantize grid, the
pattern cycle and clock-advance playhead follow the project tempo. FREE = the engine's own bang
interval (send `bang` messages / use the panel).

### State (DAW project / presets)
`voice` (all snapshot bodies + the morph surface via the text schema; slot 63 = the live voice),
`journal` (last value of every settable message: matrix, patterns, grids, shapes…), `reel`
(embedded float WAV with cue-point splices when ≤ 60 s) / `reel_path`, `panel` (surface-side
state), `midimap`. Parameters are saved by the host.

## Tests
* `make -C plugin/tests` — engine identity gate + multi-instance + MIDI/poly + dispatch checks.
* `make -C plugin/tests clap` — loads the built CLAP, records noise through the audio input,
  plays it back, sends MIDI notes/CC, checks latency reporting and a state save/load into a
  second instance.
* `make -C plugin/tests host && node web/test_panel_engine.mjs` — **panel × engine**: every panel
  control driven through the panel brain into the hosted engine (`plugin/tests/engine_host.c`, a
  line-protocol host), asserting the engine's own state afterwards (`get_params`, `snapbuf_get`,
  `morph_state`, `matrix_dump`, the status struct); any engine error fails the case. 143 cases.
* CI: `.github/workflows/plugin-build.yml` (Linux + macOS) runs both and uploads `plugin/bin`.

## Known limits / next
* The Linux GUI needs `libwebkit2gtk-4.0/4.1` installed (DPF dlopens it); without it the plugin
  runs headless (parameters + MIDI still work).
* Reels longer than 60 s are not embedded in the project — export the reel (EXPORT REEL) and it is
  reloaded from that path.
* `sphere_kick`/Bencina scatter still use libc `rand()`; harmless but not per-instance deterministic.
* The web-view GUI has been verified headless in Chromium; DAW-hosted screenshots on macOS/Linux
  are the owner's hands-on gate.
* MIDI NOTE (the pitch inlet knob) is inert once a MIDI note has been received: the engine hands
  the grain pitch destination to the `midi` message stream (engine rule, `midi_msg_active`).
